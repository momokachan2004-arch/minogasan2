# 定期更新の運用メモ

`campaigns.js` のキャンペーン情報を、人手を減らしつつ正確に保つための手順。
「全自動で信じる」はしない。**機械が下書き → 人が承認** の形にする。

---

## 1回のサイクルでやること

### A. 既存エントリの再確認（`automation/sources.json` の巡回）

`sources.json` の各 URL について：

1. 公式ページを取得する。
2. 次を読み取る（**公式サイトの文章は転載しない。自分の言葉で要約する**）：
   - いまのオファー内容（無料期間◯日 / ◯か月◯円 / 入会特典 など）
   - 無料期間の長さ（日数）
   - 受付締切日。**終了日の告知がなければ `deadline: null`（通年）**
   - 対象者（新規のみ、過去未利用者のみ、など）
3. `campaigns.js` の該当エントリと比べる：
   - 変わっていた → 内容を更新し、`lastChecked` を実行日、`source: "公式"` にする。
   - ページが 404 / オファーの記載が消えた → **エントリ削除を提案**（勝手に消さず PR で）。
   - 取得できない / 記載が曖昧 → **変更しない**。PR 本文に「確認できず」と書く。

### B. 新規候補の洗い出し（任意）

`"<サービス名> キャンペーン"` などで軽く検索し、巡回リストにない新しい無料トライアル／期間限定特典を見つけたら、
`automation/CANDIDATES.md` に「サービス名・内容の要約・締切・公式URL・確認状況」を追記する。
**`campaigns.js` には直接入れない**（人の確認待ち）。

### C. PR を出す

タイトル：`campaign refresh YYYY-MM-DD`
本文に必ず含める：

- ✅ 更新した項目（何がどう変わったか）
- ⚠️ 確認できなかった項目（理由：JS描画／アクセス不可／曖昧）
- 🆕 新規候補（`CANDIDATES.md` へ追記したもの）
- 🗑️ 削除を提案する項目（理由つき）

---

## 守るルール（保守的に）

- 公式ページの取得に**成功して**、かつ条件が**明確な**ものだけ `campaigns.js` に載せる／更新する。
- 終了日が明記されていなければ `deadline: null`。推測で日付を入れない。
- `title` / `detail` は運営の要約。サイトの文言をコピペしない（著作権）。
- 金融・通信の「〜◯/◯まで」の期限モノは自動確認が外れやすい。原則ここでは扱わず、手動運用にする。
- 迷ったら「載せない・変えない」。誤った `残り◯日` は、このアプリが防ぎたい損害そのもの。

---

## 人（運営）がやること：各サイクル

1. 届いた PR を確認（だいたい 10〜15 分）：承認 / 修正 / 却下。
2. マージする。
3. `見逃さん` フォルダをホスティング（Netlify など）に再アップして反映。

---

## スケジュール実行の設定（あとで）

GitHub にこのリポジトリを push したあと、`automation/ROUTINE_PROMPT.md` の内容で
「1〜2週ごとに上記 A〜C を実行して PR を出す」スケジュール済みタスクを設定する。
