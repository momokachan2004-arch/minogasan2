# 見逃さん β（v1・Webアプリ）

サブスク・キャッシュレス決済の「無料期間」「割引」を見逃さないためのアプリです。
企画書 `minogasan_mvp_kikaku_更新版0828.md.docx` と `minogasan_prototype.jsx` をもとに、
**ビルド不要の単一Webアプリ**として実装したものです。

```
見逃さん/
├─ index.html              ← アプリ本体（これを開く）
├─ campaigns.js             ← 掲載キャンペーンのデータ（ここだけ編集すればOK）
├─ campaigns編集ガイド.md    ← campaigns.js の追加・修正・削除・反映の手順
├─ manifest.webmanifest     ← PWA（スマホのホーム画面アプリ）用の定義
├─ sw.js                    ← Service Worker（オフライン用キャッシュ）
├─ icon-192.png / icon-512.png / icon-maskable-512.png  ← アプリアイコン
├─ ローカルで開く.bat        ← ダブルクリックでローカルサーバー起動（任意）
├─ _server.ps1              ← 上記batが使う簡易サーバー
├─ automation/              ← 定期更新の下準備（巡回リスト・運用メモ・スケジュール指示文）
└─ README.md
```

---

## 使い方（動かす）

### かんたん：`index.html` をダブルクリック
既定のブラウザで開きます。インターネット接続が必要です
（React とフォントを CDN から読み込むため）。

### 通知まで含めて試すなら：`ローカルで開く.bat` をダブルクリック
`http://localhost:8777/` でアプリが開きます。
ブラウザ通知（終了間近リマインド）は `file://` では許可できないため、
通知の挙動を確認したいときはこちらを使ってください。
ウィンドウを閉じるとサーバーは止まります。

> スマホで確認したいときは、同じことができる無料ホスティング
> （Netlify Drop / Cloudflare Pages / GitHub Pages など）に
> このフォルダごとアップロードして、その URL を配布します。
> 宣伝用の Bitly 短縮 URL も、その公開 URL に対して発行します。

## キャンペーンを追加・更新する

`campaigns.js` の `window.CAMPAIGNS` 配列を編集するだけです。
1件の書き方（ファイル冒頭のコメントにも記載）:

```js
{
  id: 3014,                     // 他と重複しない数値。既存のものは変えない
  service: "サービス名",
  icon: "🎬",                   // 絵文字1つ
  category: "動画",             // 動画 / 音楽 / 雑誌 / フード / 買い物 / くらし
  title: "初回1か月無料",        // ← 公式サイトの文章を転載せず、自分の言葉で要約する
  detail: "新規登録が対象",
  url: "https://example.com/",  // 公式の案内ページ
  deadline: "2026-09-30",       // 公開されている受付締切日。終了日の告知がない“通年”トライアルは null（一覧で「通年」表示）
  freeDays: 30,                 // 無料期間の長さ（日数）。還元系など無料期間が無いものは null
  hasCancellation: true,        // 解約の概念があるか。還元系など解約不要なら false
  addedAt: "2026-08-29",        // このアプリに載せた日。新着通知の基準になる
  tags: ["shukatsu", "tanshin"],// ★任意。状況タグの id（複数可）。付けると、その状況を
                                //   選んだ人のホーム「あなた向け」に出て、新着通知の対象になる
  lastChecked: "2026-08-29",    // ★任意。公式で条件を確認した日。カードに「✓ 8/29 確認」と表示
  source: "公式"                // ★任意。"公式"／"プレスリリース" など。未記入＝未確認（詳細画面に「未確認（サンプルデータ）」）
}
```

保存してブラウザを再読み込みすれば反映されます。

- **残り日数**は `deadline` と今日の日付から自動計算されます（固定値は持ちません）。
- **利用開始日**をユーザーが記録すると、`freeDays` から「個人の無料期間終了日」を自動計算します。
- `hasCancellation: false` のキャンペーンには「利用開始日を記録」を表示しません。
- `tags` 未指定でも一覧には通常どおり出ます。付けたものだけが「あなた向け」に載ります。

状況タグの一覧（`kosodate` / `kaigo` / `shukatsu` / `ninshin` / `tanshin` / `senior` / `kenko`）は
`campaigns.js` の `window.SITUATION_TAGS` で編集できます。ラベルもここで変えられます。

> **2026-08-29 データ棚卸し済み**：最初に入れていた作り話のサンプル（架空の締切／実在しない
> キャンペーン／`example.com` リンク）はすべて削除しました。現在の `campaigns.js` は
> 「確認済み6件（公式で条件を確認・`lastChecked`/`source` 付き）＋ 未確認2件（実在サービスだが
> 未確認、詳細画面に『未確認（サンプルデータ）』と表示）」の計8件です。
> 外した実在サービスの再確認リストは `automation/CANDIDATES.md` にあります。

**deadline の考え方（重要）**：「初月無料」「初回◯日無料」のように誰でもいつでも始められて締切の
告知が無いものは `deadline: null` にします（一覧で「通年」表示、「残り◯日」は出しません）。
`deadline` に日付を入れるのは、公式が「◯月◯日まで」と受付締切を告知しているキャンペーンだけです。

## 実装済みの機能（企画書 v1 Must Have）

| # | 企画書の項目 | 実装 |
|---|---|---|
| 1 | キャンペーン一覧＋緊急度順ソート | ○ 残り日数の少ない順。締切超過は末尾 |
| 2 | 緊急度の色分け＋「まもなく終了◯件」サマリー | ○ 残り3日以内＝赤 / 7日以内＝橙 / それ以外＝緑。サマリーはタップで絞り込み |
| 3 | カテゴリ絞り込み（「すべて」含む） | ○ ホームのタブ＋カテゴリ画面。動画/音楽/雑誌/買い物/くらし（`campaigns.js` の `CATEGORIES` で増減可） |
| 4 | フォロー機能（キャンペーン単位／サービス単位） | ○ 「フォロー中」タブ＝お気に入りキャンペーン＋フォロー中サービスのみ。**カテゴリの「新着を通知」は通知専用**で、フォロー中には入らない（別物として分離） |
| 5 | 終了間近リマインド（1件につき最大2回、基準日切替、オン/オフ） | ○ 追加時通知＋終了3日前通知。未登録＝受付締切基準／登録済み＝個人の終了日基準 |
| 6 | 個人の利用開始日トラッキング | ○ 記録すると専用表示に切替。解約概念のないものには非表示 |
| 7 | 検索（サービス名） | ○ サービス名＋キャンペーン名で絞り込み |
| 8 | パーソナライズ（任意・関心/状況タグ、2階建て） | ○ 初回は任意入力、未入力でも一般通知は届く。選んだ状況タグに `tags` が一致するキャンペーンをホーム「あなた向け」に表示＋新着通知の対象に。設定でいつでも変更・解除 |
| — | 初回同意画面／免責事項／プライバシーポリシー／全データ削除 | ○ すべて実装。データは端末内（localStorage）のみ |
| — | 表示テーマ | ○ 端末設定に追従（ライト／ダーク）。設定で手動固定も可。低コントラストだった補助文字も調整済み |

### 通知についての注意（この方式の限界）
**通知はアプリを開いた（または再表示した）タイミングで条件判定**します。
アプリを閉じている間も確実に届くプッシュ通知には、プッシュ用サーバー、
またはネイティブの端末通知（後述の Capacitor 化 / Expo 版）が必要です。免責事項にもその旨を明記しています。

## スマホアプリとして使う（PWA）

このフォルダには PWA（Progressive Web App）用のファイル（`manifest.webmanifest` / `sw.js` / アイコン）が入っており、
**ホスティングに公開すれば、スマホのホーム画面アプリとしてインストールできます。**

1. フォルダごと無料ホスティングに公開（Netlify Drop / Cloudflare Pages / GitHub Pages など。https で配信されること）
2. スマホでその URL を開く
   - iPhone（Safari）：共有ボタン →「ホーム画面に追加」
   - Android（Chrome）：メニュー →「アプリをインストール」／画面下のバナー
3. アイコンから起動すると、アドレスバーの無い全画面表示になり、初回オンライン後はオフラインでも一覧を見られます

> `localhost` や `file://` ではインストールできません（Service Worker は https か localhost 限定）。
> `ローカルで開く.bat`（localhost）ではインストール可否の確認まではできますが、実機テストは公開 URL が必要です。

### 「ストアに出す／閉じていても届く通知」まで行くなら
今のコード（HTML/CSS/JS）を **Capacitor** でネイティブアプリの殻に包むと、
`.apk`（Android）/`.ipa`（iPhone）が作れて、**端末のローカル通知**（アプリを閉じていても「終了3日前」を出せる）が使えます。
必要なもの：Node.js、Android は Android Studio、iPhone は Mac ＋ Apple Developer 登録（年 $99）。
このリポジトリの構成のまま移行できるよう作ってあります（`window.CAMPAIGNS` などの分離はそのため）。

## データの持ち方・プライバシー

- 保存先はすべて **利用者の端末のブラウザ内（localStorage）**。サーバー送信なし。
- 保存内容：お気に入り、フォロー、利用開始日、関心カテゴリ、通知設定、通知履歴。
- 設定画面の「登録データをすべて削除」で全消去できます。
- キャンペーン説明文は公式サイトの文章を転載せず、要約して掲載する運用前提です。

> 注記：利用履歴は個人情報保護法上の「要配慮個人情報」には当たりませんが、
> 通常の個人情報として適切な取り扱いが必要です。ユーザーが増えた段階で
> 専門家（弁護士等）への確認を推奨します（これは確定的な法的助言ではありません）。

## 次の一手（開発を進めるなら）

1. 掲載キャンペーンを実データで 20〜30 件そろえる（当面は手動キュレーション）
2. 無料ホスティングに公開 → スマホでホーム画面に追加して実機確認 → Bitly で施策ごとの短縮URLを発行 → クリック数で効果測定
3. 反応を見てから、閉じていても届く通知やストア配信が必要なら Capacitor でネイティブ化

### 定期更新（半自動）
`automation/` にひな形を用意済み。`git` 初期化＆初回コミットは完了しているので、あとは GitHub に push するだけ。
- `automation/sources.json` — 再確認する公式ページの巡回リスト（安定した無料トライアル中心）
- `automation/CURATION.md` — 1サイクルでやること／守るルール／人がやること
- `automation/ROUTINE_PROMPT.md` — スケジュール済みタスクにそのまま貼る指示文
- `automation/CANDIDATES.md` — 未確認の新規候補置き場（`campaigns.js` に入れる前の待機列）

流れ：スケジュールタスクが 1〜2週ごとに巡回 → 差分を **PR（承認待ちの変更提案）** で出す → 人が 10〜15分でレビュー＆マージ → ホスティングへ再アップ。

### 対象カテゴリをどこまで広げるか（メモ）
キャンペーンは無数にあるが、「見逃さん」の価値は **締切がある＝見逃すと損をする** ものに絞ると立つ。

- **相性が良い**：無料期間つきサブスク、クレカ・証券口座などの期間限定の入会特典（ポイント/現金）、
  キャッシュレス還元、ふるさと納税の期限、通信の乗り換えキャンペーン
- **相性が悪い**：常時○%還元など締切のないもの（「見逃す」概念が弱く、一覧を薄める）
- データ構造はカテゴリ追加に対応済み（`campaigns.js` の `window.CATEGORIES` に足すだけ）。
  クレカ系は `freeDays: null` / `hasCancellation: false` で「入会特典」型として今の構造のまま扱える。
- 増やす基準は「そのカテゴリで常時 5〜10 件、鮮度を保って手動更新できるか」。
  無理なく回せる範囲から広げ、回らなくなったら畳む。将来は種類ラベル（無料期間／入会特典／割引）での絞り込みも検討。
